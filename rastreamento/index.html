Setup de Tracking — GTM Web + Server

Registro completo da estrutura de rastreamento configurada para a Legado & Família: dois containers do Google Tag Manager, rastreamento client-side e server-side via Stape.io, e os testes que confirmam que tudo está recebendo e desduplicando eventos corretamente.

Visão geral

Dois containers, um só propósito

Montamos a estrutura de rastreamento em duas camadas — uma que roda no navegador do visitante, outra que roda em um servidor próprio — pra capturar o máximo de eventos reais possível, mesmo com bloqueadores de anúncio e restrições de cookies cada vez mais comuns.

Client-side

Container Web

GTM-NDPCSCS

Instalado direto no site (programas.legadoefamilia.com). É quem carrega o Meta Pixel, o GA4 e a tag do Google Ads no navegador de quem visita a página, e dispara os eventos assim que eles acontecem.

Server-side

Container Server

GTM-M6CGJ27D

Hospedado via Stape.io, num subdomínio próprio do cliente. Recebe os eventos do container Web e reenvia pro Meta pela API de Conversão, direto do servidor, driblando bloqueios do navegador.

Container Web · GTM-NDPCSCS

Quando o cliente abrir uma nova etapa de venda (loja, checkout próprio, etc.), é só ativar a tag correspondente — sem precisar configurar nada do zero.
Container Server · GTM-M6CGJ27D

Rastreamento via servidor, com domínio próprio

Em vez de usar um domínio genérico da Stape, configuramos um subdomínio próprio do cliente pra hospedar o container server — isso evita bloqueios de terceiros e mantém a marca do cliente na URL de rastreamento.

Por que isso importa: navegadores (Safari, Firefox) e bloqueadores de anúncio filtram cada vez mais pixels que rodam só no navegador do visitante. Rodando a API de Conversão do Meta a partir do servidor, o evento chega ao Meta mesmo quando o pixel do navegador é bloqueado — aumentando a taxa de eventos recebidos e a qualidade de correspondência (Match Quality) da conta.

O que "desduplicado" quer dizer, em bom português: o pixel do navegador e a API de Conversão do servidor enviam o mesmo evento em paralelo (é assim que se faz certo, redundância é bom). O Meta usa um ID de evento em comum pra reconhecer que as duas chegadas são o mesmo acontecimento — e conta só uma vez. Testamos isso especificamente e confirmamos que está funcionando: nenhum evento está sendo contado em dobro nos relatórios do Meta Ads.
